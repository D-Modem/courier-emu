## Passive live capture

Read-only SSH inspection and a bounded 65-second `tcpdump` on Asterisk
(`192.168.88.122`, TCP/UDP 5060) ran around a single optimized 403/Apple call to
6312. No PBX configuration or logging levels were changed. Capture reports zero
kernel drops. Hook release and a clean local `NO CARRIER` were verified.

Relevant transaction, 2026-10-22 NZDT:

```
11:33:19.043811  10.69.111.3:34826 -> Asterisk:5060  INVITE sip:6@192.168.88.122
11:33:19.044205  Asterisk -> gateway               401 Unauthorized
11:33:19.111201  gateway -> Asterisk               INVITE sip:6@192.168.88.122
11:33:19.111817  Asterisk -> gateway               484 Address Incomplete
```

The second INVITE is the normal authentication retry, not another call. No
INVITE for 6312, or outbound call to that extension, appears in the capture.
The capture contains other endpoints' periodic OPTIONS/REGISTER traffic, which
should not be mistaken for calls generated by this experiment.

The retained codec TX independently decodes as **6312**. Host-side codec DTMF
detection times are approximately 11:33:17.603, .753, .902 and 11:33:18.041;
these are not exact DAC playback timestamps. The gateway's INVITE follows the
fourth codec digit by about one second. We cannot yet distinguish missing
physical DTMF recognition from gateway digit-map/translation behavior. Do not
conclude from this evidence alone that it dials immediately on the first digit.

This attempt does **not** reach the requested modem extension. It is therefore
not a valid modem negotiation/interoperability test yet. Next investigate the
actual gateway digit collection, physical DTMF level/timing and dial plan.

## Why historical CDR inspection was inconclusive

- CDR is enabled, but unanswered and congestion logging are disabled.
- CEL is disabled; file logging contains only notices/warnings/errors.
- No matching answered CDR exists for our earlier attempts.
- CDR timestamps use GMT; local PBX/Mac timestamps use NZDT (+13).
- Before the controlled retry, Master.csv last changed at 09:07:25 NZDT,
  before the 09:41/09:42 extension attempts.

Absent CDRs alone did not establish whether a request arrived. The SIP capture
above is the decisive evidence.
